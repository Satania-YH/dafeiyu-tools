## 一、边不只用余弦 —— 7 类边 + 概率式叠加

**它的做法**（`docs/data-and-edges.md`）

| 类型 | 判据 | 权重 |
|---|---|---|
| `explicit` | 人工固化 | 1.0，永不剪 |
| `entity` | 同一实体：文件路径 / URL / UUID / hash / `` `反引号代码` `` / 文件名 / 邮箱 / IP / 版本号 | `0.26 + 0.68×稀有度`，≤0.86 |
| `mentions` | 正文**原样出现**某技能 / MCP / 插件名（边界匹配） | 0.92，不占度数配额 |
| `project` | 同项目名且**跨工作区**（同库同项目不连） | 0.52 |
| `keyword` | 共享稀有词（df ≤22% 且 ≤70 条），≥2 个且 Jaccard ≥0.16 | `0.3 + 0.4×min(1, jac×1.7)` |
| `semantic` | 稀有词签名重叠 ≥0.18 且共同词 ≥4 | `0.12 + 0.6×sim`，**上限 0.58** |
| `hebbian` | 同会话里被一起注入 / 检索 / 访问 | 按共激活计数（会话长度阻尼） |

**权重是概率式 OR 叠加**：`1 - Π(1-w)`，不是相加。

### 借什么

**把 `semantic`（纯余弦）的权重上限压到 0.58。**

理由：余弦相似度「看着像」≠「真是同一件事」。

### 为什么值

和我们的实测撞上了：

| 我们的 cos 分布 | 条数 | 占比 |
|---|---|---|
| 0.60–0.65 | 973 | **62%** |
| 0.65–0.70 | 358 | 23% |
| 0.70–0.80 | 218 | 14% |
| 0.80–0.90 | 81 | 5% |
| 0.90+ | 16 | 1% |

那 973 条 0.6–0.65 的弱边，在它那儿**根本进不了图**（它剪 `w < 0.3`）。
纯余弦撑不起「语义相近」的举证责任 —— 这个判断被一个独立项目验证了。

### 我们怎么用

- 保留余弦作为**其中一类**边，权重上限压到 0.55–0.6
- 补 `entity` 类：`graph.json` 里节点文本含路径（`D:/...`、`E:\...`）、文件（`*.js/*.py/*.ps1`）、
  版本号（`1.0.7`）、工具名（`ComfyUI`/`bge-m3`/`Ollama`）—— 这些是真硬证据
- 补 `hebbian`：`graph.json` 的节点若来自同一 `sessionId`，算共激活
  （需要大肥鱼在导出时带上 `sessionId`，目前节点没这个字段）

**注意**：我们的 `graph.json` 现在只有 `cos`，做七类边需要重新导出。

## 二、每条边带 `why` —— 人能看懂的一句证据

**它的做法**：边不是只有 `{s, d, w, t}`，还有 `why`。
详情面板里每条邻居都带「为什么连」的证据 + 权重条。

例：
```
keyword · 0.30 · 共享关键词：镜像站
entity  · 0.72 · 同一路径 E:\ComfyUI\models
```

### 借什么

边数据结构里加 `why: string`。

### 为什么值

`cos: 0.643` 对人毫无意义，只会让人怀疑这个连接是瞎凑的。
「共享关键词：镜像站」立刻能判断对不对。

**这也是「可审计」的一部分** —— 和 `graph-excluded.json` 同一个精神：
不盲信算法，每一步能回查。

### 我们怎么用

在 `export-graph.py` 里算边的时候，顺手记下判据：

```python
def why(a, b, cos):
    shared = set(kw(a)) & set(kw(b))
    if shared:
        return f"keyword · {cos:.2f} · 共享关键词：{'、'.join(list(shared)[:3])}"
    return f"semantic · {cos:.2f}"
```

## 三、剪枝：全局贪心 + 度数上限

**它的做法**
- 按 `w + 跨工作区加成` 排序
- **两端都还有额度**才收边
- 每节点度 ≤ 16
- `w < 0.3` 不进图
- `mentions` 和 `explicit` 不受度数上限约束（来源是标签，不是记忆的邻居）

### 为什么值

| 项目 | 节点 | 边 | 平均度 |
|---|---|---|---|
| 它实测 | 823 | ~2800 | **6.8** |
| 我们 | 247 | 1565 | **12.7** |

**我们明显偏密。** 平均度 12.7 意味着每个点连 12 条线 —— 视觉上就是一团毛线球。

### 我们怎么用

- 度数上限先设 10–12（我们数据少，不用压到 16）
- 剪枝按 `w` 排序贪心，保留强边
- 剪掉的边进 `graph-excluded.json`（带 reason: `pruned`），可回查

## 四、布局按关系紧密度决定间距 ⭐ 最值得抄

**它的做法**（`docs/interface.md`）

> 先算每对节点的 `pairW`（两点间最强边的权重），再定
> - 最小间距：`26 + 44*(1-w)`
> - 弹簧静止长度：`26 + 96*(1-w)^1.35`
>
> 证据越硬的两点贴得越近，没关系的一对自然疏开（52px 起步）。
> **于是强关联结成核、弱连接散在外围，图本身就能读出结构，而不是一层均匀铺开的网格。**

### 借什么

力导向的弹簧长度**由边权驱动**，不是固定值。

### 为什么值

这直接解决本项目最大的视觉问题：

> 0.6 阈值的边占 62%，默认力导向会画成一团均匀的毛线球；
> 但如果把阈值调到 0.7，235 个可见节点里 64 个变孤立 —— 更糟。

**按边权定间距让强弱自然分层**，既不用丢掉弱边，也不用被弱边拖成一坨。

### 我们怎么用

```
minDistance(link) = 26 + 44 * (1 - cos)
springLength(link) = 26 + 96 * Math.pow(1 - cos, 1.35)
```

`d3.forceLink().distance(springLength)` + `d3.forceCollide().radius(minDistance/2)`。

## 五、记忆体检 · 六类失效模式

**它的做法**（`lib/host/graph.js` 的 `auditHygiene`，思路来自 `mashanglinyu/luanyujia-workbench`）

| 检查 | 判据 |
|---|---|
| 疑似重复 | 稀有词签名 Jaccard ≥0.86 且长度比 ≥0.6 |
| 该更新了 | 还挂 `active`，但同项目里有更新、更重要、共享 ≥3 关键词的记忆覆盖了它 |
| 关系是凑的 | 度数 ≥10 但平均边权 <0.45 —— 连接多而都弱 |
| 超重 | 正文超过本库最重的 3%（下限 600 字） |
| 没人读过 | 写下 3 天以上、`hit_count` 为 0、还 active |
| 孤立 | 一条边都没有 |

**阈值按当前库的分位数算，不写死** —— 库还小的时候不会满屏报警。

**只诊断，不改任何记忆。**

### 借什么

六项判据 + 「按分位数算阈值」这个做法。

### 为什么值

我们的体检报告（`记忆系统体检-2026-11-23.md`）列的问题，和它这六项高度重合：

| 我们的发现 | 它的对应检查 |
|---|---|
| memories.json 与 db 16 条重复 | 疑似重复 |
| `access_count=0` 的 29 条（28 条 context）| 没人读过 |
| 13 个孤立点 | 孤立 |
| 62% 弱边 | 关系是凑的 |
| insights 有 900+ 字长文 | 超重 |

**它把这个需求标准化了，而且给了"不写死阈值"这个关键细节。**

### 我们怎么用

- 检查项改为适配我们的六类节点（`judgment` / `said` / `rule` / `insight` / `memory` / `voice`）
- **必须遵守 RULES.md 的 R2**：不做评分、不做进度条。只给清单，不给"健康度 82 分"
- 出口放在左侧面板「记忆体检 N 项」，点一条跳到对应节点

## 六、出处：写这条记忆时主人说了什么 ⭐ 补断链

**它的做法**

> 星图去读 DSH 自己的会话转写（`$DSH_HOME/sessions/**/session.v4.jsonl.zstd`，
> 每个文件是多帧拼接的 zstd，星图自己拆帧解压），
> 取「这条记忆写下来之前最近的一条真人消息（45 分钟内）」，
> 在详情面板顶部原样引用，并标注「出自会话 `xxxxxxxx` · 说过这话 13 分钟后写下」。

**关键**：这是只读旁证，**它不给记忆连边，只回答「这话从哪来」**。

### 为什么值

直接补上体检报告 **P0-1** 说的那个断链：

> insight 无法回溯到 event。`insights.source` 全部是 `'agent'`，没有字段指向来源。

加字段要改写入路径（大肥鱼这轮不做）。**它是用「时间邻近」绕过去的 —— 不需要改任何库。**

### 我们怎么用

`graph.json` 的 `insight` 节点目前**没有 `ts`**（只有 `category` / `importance`）。
要做得先让导出一层从 `mnemon.db` 的 `created_at` / `stored_at` 取时间，然后：

```
对每个 insight：
  找 events.jsonl 里 ts 在其之前、45 分钟内的最后一条 heard（或 utterance）
  → 详情面板顶部引用 + 「×分钟前说的」
```

**这是二期最有性价比的一项。**

## 七、证据链：A→B 到底怎么连上的

**它的做法**
- 左键选一个 + `Shift` 点另一个
- 图上亮出金色路线，沿途节点标 1/2/3…
- 底部面板逐步写明每一跳的**类型、权重、证据**
- 上限 6 跳
- 代价用 `-log(w)`，所以**优先走证据最硬的那条**
- 找不到就直说找不到，不硬凑
- 前端能自己算（服务端路由对不上时降级到本地）

### 借什么

`-log(w)` 作为最短路代价 —— 这一条是整个设计的点睛之笔。

### 为什么值

**「权重」和「距离」是反的。** 直觉上用 `1-w` 或 `1/w` 都行，但 `-log(w)` 是唯一
满足「两段 0.5 的边等于一段 0.25 的边」的度量 —— 也就是概率的乘法关系。

他们选 `-log(w)` 而不是 `1-w`，说明真的想过权重是「概率」不是「分数」。

### 我们怎么用

```
Dijkstra，边代价 = -Math.log(w)，w 是 cos（下限 clamp 0.01 防止 log(0)）
跳数上限 6
```

247 节点跑 Dijkstra 是微秒级，不需要任何优化。

## 八、视觉与性能手段（实测有效）

### 8.1 连边批处理

> 按「颜色 + 量化透明度」归并成十几条 `Path2D`，每批一次 `stroke`
> （原来 3000+ 条边各自 `beginPath`/`stroke`）

**我们的场景**：1565 条边，按透明度量化到 8 档 + 5 种颜色 → 40 个批次。
从 1565 次 `stroke` 降到 40 次。

### 8.2 光点贴图缓存

> 每种层级色只渲染一次发光球到离屏 canvas，之后全是 `drawImage` 缩放
> （原来每帧给 940+ 节点各建两个径向渐变）

**我们的场景**：6 种 kind → 6 个离屏发光球。每帧 247 次 `drawImage`，
比每帧 494 次 `createRadialGradient` 快一个数量级。

### 8.3 按格点亮（生长动画）

> 世界坐标按 900 单位切格，格子按「离视口中心距离」排序，每格错开 110ms，
> 格内按重要度先亮 → 「一波从中心向外铺开」的生长

**我们 247 节点**：约 1–1.5 秒长满。可以不急，二期再加。

### 8.4 传输瘦身（我们用不上）

> 边改成「节点下标」不用长 id，节点只留 12 个绘制字段。
> 实测 2,646,434 字节/1895ms → 831,444 字节/681ms（-69%）

**我们 `graph.json` 315 KB**，一次加载完事。不需要。

### 8.5 悬停「减淡」不「消失」

> 非邻居节点降到 45% 亮度、非相邻边降到 34%，被悬停的额外放大 1.7×
> —— 靠「亮起来」抢注意力，而不是把别人按黑

**这条纯视觉，但体验差很多。** 我们照做。

## 九、其它细节

### 9.1 通用文件名不算跨项目证据

> 跨工作区时，`package.json` / `index.ts` / `app.html` / `server.mjs` / `README.md`
> 这类叶子名**不算实体证据** —— 两个项目各有一个 `package.json`，不代表讲同一件事。
> 同一条记忆库内部仍然算。这条单独救回 61 条「假的跨项目桥」。

**我们对应**：`events.jsonl`、`mnemon.db`、`config.ini` 这类通用名不能当 entity 边证据。

### 9.2 纠错：把算错的关联按掉

> 详情面板每条邻居右侧一个 `×`：自动推断的边 → 记进屏蔽表（`mutes`），重建也不再连；
> 人工策展的边 → 直接删。误点 8 秒内可撤销。

**但注意 RULES.md R1**：我们只读，不能真删。可以做「前端屏蔽」，存在 `localStorage`，
不写回任何库。

### 9.3 12 秒轮询自动刷新

> 页面每 12 秒比一次 `sig`，别的会话写了新记忆会自动长出新星点

**我们不需要实时**，但可以做一个「重新加载」按钮，读最新 `graph.json`。

## 附：它的技术栈（供参考）

```
lib/
  index.js       插件入口：9 个工具 + 每轮注入提示 + /api/memory-nebula
  host/
    nebula.js    门面：索引 / 缓存 / 巡检 / publicGraph / detail / bridge
    graph.js     建图、打分、剪枝、auditHygiene
    recall.js    seed + 扩散激活检索
    bridge.js    补充包：ids → 扩散 → 排除已读 → 预算内挑几条
    ledger.js    注入账本：谁什么时候注入过什么（跨插件共用）
    adapters/    meow / notes / sqlite / ingest
    http.js      路由
  web/
    app.js       状态、面板、筛选、命令面板、导出、时间轴（164 KB）
    render.js    2D 星云：力导向 + 区块点亮 + Path2D 批处理（77 KB）
    space3d.js   3D 星系 / 时间螺旋：WebGL 光点（65 KB）
```

**零框架**：纯 vanilla JS + Canvas + 原生 WebGL。没有 React / Vue / D3 运行时依赖
（但 `d3-force` 的力模型思路被借鉴）。

它的实测性能：874 节点 / 3000+ 边，2D 帧间隔中位 16.7ms（60fps）。
