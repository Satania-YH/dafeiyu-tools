## R1 · 每日记忆新增（统计）

**需求**：能看出每天新增了多少条记忆、各是什么类型。

**含义**
- 按天聚合：每个自然日新增节点数
- 按 kind 拆分：judgment / said / rule / insight / memory 各自新增多少
- 时间口径：`ts` 转本地（UTC+8），不用 `day` 字段（对 meta 恒为 0）

**数据可行性**
- `events.jsonl` 的 `ts` 可直接按天分桶 ✅
- insight 有 `created_at`（需导出时补进节点）⚠️
- memory 目前没有时间字段，导出一层要补 ⚠️

**呈现位置建议**
- 顶栏统计数字的扩展，或左栏底部
- 小柱状图/条带：横轴日期，纵轴条数，按 kind 分段着色；

## R2 · 记忆日报 / 周报

**需求**：控制台里能看「今天新增了什么类型、什么内容」的日报，以及周报。

**日报内容**
- 日期
- 当天新增条数（总数 + 分类）
- 当天新增的记忆条目列表（可点击跳到星图）
- 当天有没有「改口」（revise）/ 「被覆盖」（同主题更新）

**周报内容**
- 一周七天的条数趋势
- 本周新增最多的类型
- 本周有哪些「第一次」出现的话题（topic 新出现）
- 本周孤立节点变化（有没有越积越多的死记忆）

**注意约束（RULES.md R2）**
- ❌ 不做「本周记忆健康度 87 分」
- ✅ 只给条数、类型、日期、清单

**呈现位置建议**
- 顶部「诊断」页里再分 tab：日报 / 周报 / 问题清单
- 或左栏加一个「日报」入口

## R3 · 记忆之间的串联（已在 demo 验证，需正式化）

**需求**：记忆之间有串联关系，串联效果要表现出来。

**demo 现状**
- 已有：连线按 cos 强度着色，强边更亮
- 已有：沿强边流动的光点（`buildFlowParticles`）

**正式版要加强**

## R4 · 星点质感：像真实银河，不要太闪

**需求原话**：「每个记忆点要像银河里的星星一样，不要太闪，可以参考真实的银河星星效果」

**这一条是对 demo 最重要的修正。**

**当前 demo 的问题**
- Bloom 太强（0.95 / 0.62 / 0.30），所有点都在发光爆炸
- 中心亮核过曝，像霓虹灯不像星空
- 每颗星都有明显光晕，缺少「大小/亮度层次」

**真实银河的样子（要参考的）**
- 绝大多数星是**极小的暗点**，只有亮度和尺寸的细微差异
- 只有极少数几颗亮星有明显光晕
- 整体是「暗背景 + 密集微小亮点」，不是「一堆发光球」
- 星光偏冷白/微黄/微蓝，不是纯 RGB 饱和色
- 亮核由**密度**形成，不是由**亮度**形成

**改法**
1. Bloom 降到 0.35–0.45 / radius 0.5 / threshold 0.55（只有真正的亮星才泛光）
2. 节点基础尺寸再小：`2.0 + t * 8`（现在是 3.2 + 26，太夸张）
3. 颜色去饱和：当前六色太艳，改为「同色系但饱和度 -35%，亮度 +10%」
4. 光晕改成双层：内层锐利核心（小），外层极淡（大）—— 比例约 1:3，不是 1:1
5. 核心过曝降到 1.6（现在 2.6）
