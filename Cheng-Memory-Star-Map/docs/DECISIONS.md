## D1 · 星图的节点画什么？

节点范围决定了图的信息密度和可读性，改起来成本很高，必须先定。

### 方案 A（推荐）：只画「她的判断」+ 记忆库

| 项 | 内容 |
|---|---|
| 节点 | 63 条 committed utterance + 62 条 insights（去软删除）− 16 条重复 ≈ **109** |
| 边 | embedding 余弦 ≥0.6 现算 |
| 优点 | 图干净，每条都是真的，没有噪声。一眼能看出「她在想什么」 |
| 缺点 | 看不到「谁说了什么→她怎么想」的对应 |
| 工期 | 短 |

### 方案 B：加上「听到的话」

| 项 | 内容 |
|---|---|
| 节点 | A 的 109 + 128 条去重 heard ≈ **237** |
| 边 | 同上，可加 `sessionId` 聚类 |
| 优点 | 能看到对话输入与判断的对应关系，更像「记忆是怎么长出来的」 |
| 缺点 | 节点翻倍，视觉会挤；heard 里有 39% 重复需先清洗 |
| 工期 | 中 |

### 方案 C：全画 + 图层开关

| 项 | 内容 |
|---|---|
| 节点 | 所有类型，含 meta / voice / seed |
| 边 | 全类型 |
| 优点 | 信息最全，可按需开关 |
| 缺点 | 默认视图需大量调教；meta 占 60.7%，不默认关掉就是一锅粥 |
| 工期 | 长 |

**建议**：A 起步，架构上预留图层开关，验证可行后再加 B 的 heard 层。

## D3 · 「健康检查」做到什么程度？

`examine()` 已经给了一套字段，但有几个实测为 0（`revises` / `flips` / `tensions`）。
另外体检报告里发现的漏点（向量覆盖、heard 重复、双写重复、孤立点）`examine()` 不覆盖。

### 选项

- **A**：只渲染 `examine()` 的输出，不自己算任何东西（最保守，符合「别重写口径」）
- **B**：`examine()` 输出 + 补几个体检项（向量覆盖率、heard 去重率、跨库重复数、图孤立点数）
- **C**：完全自建健康度模型（**不建议**，与 RULES.md 第 4 条冲突）

**建议**：B。`examine()` 原样显示，另开一栏「体检补充」，明确标出这些不是 `examine()` 的口径。

## D4 · 时间轴用什么？

- `day` 字段**对 meta 恒为 0**，横跨四天，不能用
- `ts` 是 UTC，展示要转本地
- 文件顺序有 37 处倒序，不能假设有序

**建议**：一律用 `ts` 转本地；节点按 `id`（ULID，内含时间）排序。
